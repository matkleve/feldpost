## Mistakes / lessons

- Assumed `--include` on `ng test` would scope *compilation*, not just *execution* — it doesn't; `tsconfig.spec.json` includes `src/**/*.spec.ts` unconditionally, so any spec file anywhere in the app can block every other spec file from type-checking. Caught this before silently expanding scope into unrelated subsystems; used `npx vitest run <file>` directly (bypassing Angular's builder, which does its own whole-program TS check) to get a real, isolated red→green cycle for the one Sensitive-class fix that needed it.
- The `lint-specs-full.txt` discovery is worth remembering for future audits of this repo: a captured CLI-output file committed to git root will silently go stale and can end up quoted as ground truth by anyone (including an earlier version of the same audit plan) who doesn't re-run the command it captures.

# 2026-09-09 — UI primitives conformance pass

## Shipped

| | |
| --- | --- |
| `apps/web/src/styles/_reduced-motion.scss` | spinner exemption fixed — it was freezing three of nine spinners |
| `docs/audits/2026-09-09-ui-primitives-conformance.md` | all 17 `shared/ui/` primitives checked against nine rules the repo already states |
| cleanup pass | deleted `shared/ui/card` + `shared/ui/toast` (11 files, no consumer); `focus:` → `focus-visible:` in badge and select; `transition-all` → named properties in tabs and toggle-group; `bg-black/80` → `var(--scrim)`; removed three copies of `motion-reduce:` in toggle-group |

## Went wrong

- **My own reduced-motion rule from yesterday froze spinners.** The exemption
  was `:not([class*="__spinner"])`, chosen after looking at two spinner
  stylesheets and generalising from them. There are **nine** spinner classes;
  three do not carry the `__spinner` tail — `.upload-panel__thumbnail-spinner`,
  `.invite-editor__qr-spinner`, and the `hlm-spinner` primitive, which has
  `animate-spin` and no BEM class at all. Under `prefers-reduced-motion` those
  three stopped after one rotation, which reads as a hung app — the exact
  failure the exemption existed to prevent.
  **The lesson is about the shape of the check, not the count:** I wrote an
  exemption keyed on a naming convention after sampling two examples, instead of
  enumerating every element the rule would hit. A rule that suppresses behaviour
  globally needs its exception list derived from a full search, not from the
  cases that prompted it. `rg -l 'animation:[^;]*spin'` was one command and
  would have shown all eight SCSS cases immediately.
  Fixed by matching `spinner` anywhere in the class list plus `animate-spin`,
  and verified in the built CSS.

## Decisions

- **The primitives are in better shape than the design audit implied.** Six of
  the seven genuinely interactive primitives carry every applicable state. The
  audit's § S1 framing ("the primary action has no press feedback") was true of
  `button` before yesterday and was never true of the layer as a whole. Recorded
  so the next reader does not go looking for a systemic problem that is not there.
- **Inline `color-mix` in the primitive TS is not going to be fixed by the
  existing mixin.** A `cva` string cannot `@include` Sass. The answer is shared
  exported constants in TS — which `quietInteractionEmphasis` and
  `toggleOffEmphasis` already approximate — plus a guard that admits it is not
  looking at `.ts` rather than staying silent.

## Findings worth acting on

- `guard-interaction-emphasis.mjs` scans only `.scss`. Seven of its own banned
  patterns sit in the primitive `.ts` files, invisible to it.
- `registry.json`'s nine state-declaring entries and the 17 primitives are
  **disjoint sets** — no primitive declares states, so the proposed
  "assert declared states are implemented" gate has nothing to check yet.
- `shared/ui/card/` and `shared/ui/toast/` are imported by nothing. Toast is
  actively misleading: a working toast system lives in `shared/toast/`.
- `badge` and `select` use `focus:` rather than `focus-visible:` — a ring after
  every mouse click.
- Nine primitives have no dedicated spec, including `input` (56 usages) and
  `label` (49).

## Went wrong (found by the cleanup, not caused by it)

- **A live spec described wiring that never existed.** Running the
  change-completeness grep after deleting `shared/ui/toast` turned up
  `docs/specs/service/toast/toast-system.md`, which stated the toast chrome *is*
  "Spartan `hlmToast` + `toastVariants` CVA", and an acceptance criterion
  demanding "severity styling from `hlmToast` / `toastVariants`". The real toast
  has always rendered `.toast-surface` from `toast-item.component.scss`, with
  severity on `.toast-indicator` via a host class bound from `item().type`. An
  implementer following that contract would have built the wrong thing, and the
  spec lint cannot see it because the shape was valid — only the content was
  false. Both files corrected in the same change.
  **Worth generalising:** the grep-to-zero rule is written as a check on the
  thing you removed. It is also the cheapest audit of whether the specs ever
  described the thing you removed *correctly* — here the answer was no, and the
  deletion is what surfaced it.

## Decisions (cleanup pass)

- **`duration-200` in the dialog scrim stays.** The motion scale is
  100 / 150 / 250 / 300 ms and has no 200 ms step, so "use the token" would
  retime the overlay fade by 50 ms. Replacing a literal with a token that means
  something different is not a cleanup — it is an unreviewed visual change
  wearing a cleanup's clothes. Left for the owner as a scale question.
- **`--scrim` was introduced at the identical computed value** (`rgb(0 0 0 / 80%)`
  = the old `bg-black/80`). The point was to remove the last raw colour from the
  primitive layer and give sandstone somewhere to warm it, not to change how the
  overlay looks today.
- **The deleted primitives carried `TODO(spartan-v4)` headers.** If they were
  staged for a future spartan migration, that intent belongs in
  `docs/migration/`, not in an unreferenced folder that a reader has to
  disambiguate from the live `shared/toast/`. Git history holds them.
