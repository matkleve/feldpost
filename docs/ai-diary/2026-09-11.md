## What we did

**UP-26 — removed the location layer's false dependency hub.** `UploadLocationResolutionService`
was a pure facade: every one of its ~15 public methods just forwarded to one named sibling. Six
siblings (`placement`, `source-conflict`, `tray-flow`, `candidate-apply`,
`pre-resolve-orchestrator`, `disambiguation-registration`) reached back into it anyway — a
top-level import plus, in most, a lazy `Injector.get()` call — purely to invoke the sibling
method the facade only forwarded to. That was the audit's "six identical workarounds around one
hub" finding, worth 11-13 of the subsystem's 20-27 circular-import cycles depending on which
count you trust.

Traced every one of the ~20 `.resolution().xxx()` call sites across the six files by hand first,
which showed the facade only ever really *owned* two things: the `disambiguationRequired$` /
`disambiguationResolved$` event subjects. Everything else was a zero-logic pass-through to a
named sibling that already existed. Moved those two subjects (and their `notify*` methods) onto
`UploadLocationDisambiguationStoreService` — already the one genuine leaf service in this
cluster (only depends on `UploadBatchService` + pure helpers) — then had the six siblings inject
the real owning service directly instead of the facade. The facade's own public API is
byte-for-byte unchanged (still delegates to the same siblings), so nothing outside this cluster
needed to change.

Two of the ~20 call sites turned out to be genuine mutual dependencies, not hub symptoms: before
touching anything, checked which siblings already imported each other directly (not via the
facade) to make sure a straight "just inject the real service" swap wouldn't just relocate a
cycle. `candidate-apply` already imports `tray-flow` directly (for
`applyLayerPackageChoice`/`applyAdminLevelConflictChoice`), and `tray-flow` needed
`candidate-apply` back (for `applyCandidateToGroup`/`deferGroup`) — a real two-way relationship.
Same shape for `placement` ↔ `pre-resolve-orchestrator`. Kept those two as `Injector.get()`
calls, same mechanism as before, but now correctly scoped to the two pairs that actually need it
and documented at the call site as "genuine, not a hub symptom" — instead of six services
routing through an unrelated facade for no structural reason.

Red-test-first: wrote `upload-location-dependency-cycle.spec.ts` first, a plain
file-content-grep test asserting the six siblings never import
`upload-location-resolution.service`. Confirmed all 6 assertions failed against the
pre-refactor code, then made them pass. `madge --circular src/app/core/upload` went from 27 to
24 cycles — the false-hub pattern is fully gone; the 3-cycle reduction (not 11-13) is because
most of the eliminated cycles were long chains sharing the same facade edge, and because two new
short cycles appear where the genuine mutual dependencies above are now direct instead of
routed through the facade (net honest accounting, not a hidden regression).

## What we found

- **The facade really was pure delegation, no hidden logic.** Every method on
  `UploadLocationResolutionService` was a one-line forward. This made the refactor mechanical
  and low-risk in a way "collapse the location layer" (P11) as a whole is not — worth noting for
  whoever picks up P11/UP-27 next: this cluster's hub problem and its DB-access/type-consolidation
  problem (UP-27) are separable, and the hub was the easy half.
- **Two other cycles in this area are separate problems, not this one.** The tray-producer
  adapter reaching into `disambiguation-registration`, which reaches back into the adapter
  (reverse-layering — a core adapter shouldn't need a UI-orchestrator-facing type back), and
  `UploadManagerService`'s own entanglement with the location layer via
  `candidate-apply.kickQueueAfterLocationGate()`. Both pre-date this change, both are still
  present after it, both documented rather than silently left for someone to rediscover.
- **Restarting a merged branch mid-session is cheap when done immediately.** Caught the drift
  before writing a single line against the stale plan — the only cost was the investigation
  time to re-read two new audit documents and re-verify code state directly rather than trusting
  either audit's own tables at face value (confirmed the "already fixed" claims by reading the
  actual current source, not just the doc).
