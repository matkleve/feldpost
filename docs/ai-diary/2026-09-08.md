## Decisions

- **One gate over per-area scripts.** `AGENTS.md` used to map change class → which
  script to run. That mapping is the thing that gets skipped: not from laziness,
  but because nobody holds the list. Rules out: adding a sixth "run this when you
  touch X" instruction. New checks go **into** `verify`.
- **CI without path filters.** The filtered workflows optimised CI minutes and
  cost trust: `guard-visual-behavior.mjs` asserts things about `.html` templates
  while `design-system-check.yml` filtered on `*.scss` only — so editing one of
  the templates the guard protects never ran the guard. `verify.yml` has no
  filter. The heavy jobs (Supabase contract, Deno edge tests) stay filtered.
- **Three checks enter the gate as *soft*.** Running the full gate for the first
  time showed `lint:specs` (201 errors), `lint` (151 errors + 1068 warnings, and
  `--max-warnings 0` means warnings fail) and `test` (**the test bundle does not
  compile** — ~101 TS errors, 4 unresolved imports in `*.spec.ts`) all red on
  `main`. It exits 1 today with 201
  errors that predate the gate. Hard-failing would have made `verify` red on a
  clean tree on day one, which trains everyone to ignore it; excluding it would
  have hidden the debt. Soft + a named, dated debt in
  `docs/specs/SPEC-SIZE-BACKLOG.md` is the middle. Rules out: making any other
  check soft to get a green run.
- **Archived personas stay archived.** Five live use-case docs linked a
  `use-cases-README.md` that the 2026-04-15 cleanup archived. Restoring 823 lines
  of unreviewed use-case catalogue would have made stale content look current, so
  the links now point at the archive path and say "(archived catalogue)" in the
  text. A live use-case index is a separate, owner-reviewed job (§ D5 of the audit).

## Went wrong

- **A "green" status line that was false.** `docs/specs/SPEC-SIZE-BACKLOG.md`
  claimed `lint:specs` was green (0 errors, 0 warnings). It exits 1 with 201.
  Not noticed because the `spec-lint` workflow only ran on `docs/specs/**` PRs.
  The check that would have caught it: running the gate unconditionally in CI —
  which is now what `verify.yml` does.
- **A guard everyone believed in.** `.claude/settings.json` declared a
  `PreToolUse` hook as `{matcher, action, message}`. That is not the hook schema
  (a hook entry needs a nested `hooks` array of `{type: "command", command}`),
  and `matcher` matches *tool names*, not file paths — so it was inert twice
  over, and `eslint.config.mjs` was never protected. **A config that is silently
  ignored looks exactly like a config that works.** Anything declarative that
  claims to block something needs one test that proves it blocks; the new hook
  has three (allow, block, unparseable input).
- **A stale path is invisible to a link checker when it is written in
  backticks.** `docs/design-system/…` appeared in 10 places (5 of them in
  `CONTRIBUTING.md`) after the folder moved to `docs/design/design-system/`.
  The new gate only sees markdown links. Fixed by hand; the blind spot is real
  and noted in the audit.
- **A bulk fixer needs an audit pass first.** Rewriting the stale
  `docs/design-system/` prefix also rewrote the sentence in the audit document
  that *quoted* the broken path as evidence — the fix destroyed its own
  evidence. Caught on review of the diff, not by any gate. This is
  `bulk-operation-safety.mdc` § audit-first, and it cost a re-edit.

- **`Build & Test` has been failing on `main` since at least 2026-06-23.** The
  last eight runs on `main` all concluded `failure`, each within about five
  seconds — too fast to have reached the build, and the logs have expired so the
  cause cannot be read any more. Nobody acted on eight consecutive red runs,
  which is the whole argument for A2 stated as a fact rather than a worry: a
  check nobody trusts is a check nobody fixes. Someone with repo settings access
  should look at why the jobs die in five seconds.
- **The broken test bundle is the most urgent thing found today.** Four
  `*.spec.ts` files import paths that do not exist (e.g.
  `location-resolver.service.spec.ts` imports `./auth/auth.service`, which sits
  three folders away), plus ~97 type errors. `ng build` is green, so this is
  test-only — which is exactly why it survived: the one job that would have
  caught it has been red and ignored for months.

- **The design-system pass found user-visible defects, not just process gaps.**
  The destructive button fails WCAG AA in the light theme (3.61:1, needs 4.5:1)
  and `scripts/audit-theme-contrast.mjs` has been finding it all along — the
  script is simply not called by any gate. Three of six `buttonVariants` define
  `hover:` with no `active:`, so the *primary* button has no press feedback while
  a quiet toolbar icon does. And `state-visuals.md` § Disabled — a normative
  contract — cites `apps/web/src/styles/primitives/button.scss` with
  `opacity: 0.66`, but that folder does not exist and the live primitive says
  `disabled:opacity-50`. **When a contract cites deleted code, every reading
  downstream is a guess.**
